# 架构说明

## 要解决的问题

云数据库 只读副本没有统一入口。每个副本各有自己的内网 IP 和内网域名，应用要用上它们，只有两条路：

1. 在应用里维护副本清单，自己做轮询——副本一增减就要改配置、重启应用；
2. 在副本前面放一个负载均衡器——但副本的 IP 不固定，扩容、故障重建、规格变更都会换 IP，负载均衡器的后端清单会立刻过期。

本实践解决第二条路的短板：**让后端清单自己跟上副本的变化**。应用只需要连一个固定的内网地址，副本的增减对它完全透明。

## 组件

| 组件 | 角色 | 说明 |
|-|-|-|
| **独享型 ELB（四层）** | 只读流量入口 | 内网 TCP 监听，端口与 云数据库 一致。应用把只读连接串指向它的内网 IP |
| **IP 类型后端服务器组** | 副本清单载体 | 成员是 `IP + 端口`，不绑定实例，因此可以承接任何来源的副本 IP |
| **健康检查** | 剔除不可用副本 | TCP 探测数据库端口，与注册逻辑相互独立、互为兜底 |
| **FunctionGraph 函数** | 唯一的写入方 | 每分钟运行一次，是后端清单的唯一维护者 |
| **定时触发器** | 调度 | Rate 类型，默认 `1m` |
| **OBS 状态桶** | 跨执行记忆 | 存 `active_ip.json` 与 `pending_ip.json`，函数本身无状态 |
| **LTS 日志组 / 日志流** | 可观测 | 函数每次执行输出一条结构化摘要 |
| **IAM 委托** | 运行时权限 | 函数运行期换取临时凭据，代码里没有任何密钥 |

## 两种副本发现方式

函数支持两种发现方式，用 `discovery_mode` 切换。状态机逻辑完全一致，只有「怎么拿到副本 IP」这一步不同。

### rds_api（默认）

调用 云数据库 v3 的实例查询接口，直接读回 `private_ips`。

- 函数**不需要接入 VPC**，因而不需要 NAT 网关，也不占用子网 IP；
- 没有 DNS 缓存，副本 IP 变更立刻可见；
- 需要知道副本的**实例 ID**（`rds_replica_ids`）。

### dns

解析副本的内网域名，取 A 记录。

- 副本的内网域名只在 VPC 内可解析，因此函数**必须接入 VPC**；
- 接入 VPC 后函数只有内网出口，而它还要调用 ELB / 云数据库 的区域 API 端点，**需要自行提供出网通道**（NAT 网关或 VPC 终端节点）。模板不创建这类资源——它们是保底型计费，该由使用者显式决定；
- 域名相对稳定，副本重建后域名不变，配置不用跟着改；
- 受 DNS TTL 影响，IP 变更的感知会有延迟；
- 需要知道副本的**内网域名**（`rds_replica_dns_names`）。

选型建议：默认用 `rds_api`。只有当你的运维流程本来就以域名为准、或者副本 ID 不方便下发时，才切到 `dns`。

## 后端位置：同 VPC 还是跨 VPC

注册后端成员时有一个关键参数——后端所在子网。

- **同 VPC**（`cross_vpc_backend = false`，默认）：注册时必须带上后端子网的原生 IPv4 子网 ID，模板会自动查出并注入函数；
- **跨 VPC**（`cross_vpc_backend = true`）：注册时不能带子网 ID，同时负载均衡器要开启跨 VPC 后端能力，模板会自动打开。

两者不能混：同 VPC 却不带子网 ID，或跨 VPC 还带着子网 ID，注册都会被拒。

## 子网的两个 ID

一个子网同时有两个 ID，用途不同，混用会直接导致创建失败：

| ID | 谁用 |
|-|-|
| 子网（网络）ID，即 `huaweicloud_vpc_subnet.id` | 函数的 `network_id`、云数据库 实例 |
| 原生 IPv4 子网 ID，即 `ipv4_subnet_id` | ELB 的 `ipv4_subnet_id`、后端成员的 `subnet_cidr_id` |

模板只要求填前者（`subnet_id`），后者由数据源自动查出。

## 为什么后端成员不写进 Terraform

`infra/` 里刻意**没有** `huaweicloud_elb_member` 资源。

后端成员是运行期状态，由函数每分钟维护。一旦把它纳入 Terraform 管理，下一次 `terraform apply` 就会把函数注册进来的副本判定成"配置漂移"并清掉——与整个方案的目的直接冲突。

同理，函数的 `max_instance_num` 加了 `ignore_changes`：控制台上手工调过的并发配置不该被 apply 抹掉。

## 权限模型

函数**不持有任何静态凭据**。运行期通过 IAM 委托换取：

- `context.getToken()` → 临时 token，用于 ELB v3 / 云数据库 v3 调用；
- `context.getSecurityAccessKey()` 等 → 临时 AK/SK，用于对象存储调用。

委托授予的策略：

| 范围 | 策略 | 用途 |
|-|-|-|
| 区域级 | `ELB FullAccess` | 增删后端服务器组成员 |
| 区域级 | `RDS ReadOnlyAccess` | 查询只读实例的 `private_ips` |
| 区域级 | `VPC ReadOnlyAccess` | ELB 细粒度策略的依赖项 |
| 区域级 | `VPC FullAccess` | 仅 `dns` 模式追加——函数需要接入 VPC |
| 全局 | `OBS OperateAccess` | 读写状态文件。对象存储是全局服务，权限只能在全局范围授予 |

## 数据保护

| 项 | 做法 |
|-|-|
| 状态桶 | 私有 ACL；SSE-OBS（AES256）服务端加密，不引入密钥管理费用 |
| 传输 | 所有 API 调用走 HTTPS |
| 凭据 | 全部运行期获取，代码、环境变量、Terraform 状态中均不出现 |
| 日志 | 只记录 IP 与计数，不落任何凭据 |

## 依赖与运行时

函数只用运行时自带的库：

| 用途 | 库 | 来源 |
|-|-|-|
| ELB / 云数据库 / IAM 调用 | `requests` | 运行时预置 |
| 对象存储 | `obs`（obsclient） | 运行时预置 |
| DNS 解析（dns 模式） | `socket.getaddrinfo` | 标准库 |

部署包因此只有几十 KB，不需要打依赖层，冷启动开销可以忽略。
